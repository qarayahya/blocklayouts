The Infinite Scroll block automatically loads more posts as your visitors scroll down the page. Instead of clicking "Next page" or "Load more", visitors simply keep scrolling and new posts appear underneath the existing ones. This creates a seamless, modern browsing experience that keeps visitors engaged. This is ideal for blog archives, latest posts sections, and news or article lists where you want to encourage continuous reading.

How to add this block

1. Edit the page or template where your posts are listed. This could be your Blog page, an archive template, a Single Post template, or any page that uses a Query Loop block to display posts.

2. In the editor, you'll see your list of posts. Click on any individual post item in the list to select it.

3. Look at the breadcrumb navigation at the top of the editor. It will show the hierarchy of blocks, something like "Post Template / Query Loop". Click on the Query Loop part of the breadcrumb to select the entire Query Loop block.

4. With the Query Loop selected, scroll down to the bottom of the list of posts. You'll see a + button at the end of the Query Loop.

5. Click that + button and search for "Infinite Scroll" in the block inserter.

6. Click "Infinite Scroll" to insert it at the end of the Query Loop. The block will appear as a placeholder with default text.

7. Select the Infinite Scroll block you just added. In the right sidebar under Settings, you'll see options for the block.

8. Choose between two load types: "Infinite" (auto-loads on scroll) or "Button" (user clicks to load more). Infinite type provides a seamless experience, while Button type gives users more control.

9. For Button type: Click directly on the button text in the editor (it will say something like "Load More" by default) and edit it inline. You can make it bold, italic, or change the wording.

10. For Infinite type: Click directly on the loading text in the editor and edit it inline. This is the text that appears while new posts are being fetched.

11. In the sidebar settings, you can also edit the "No More Content" text, which appears when all posts have been loaded.

How to style it

Use the style panels in the sidebar to customize the appearance:

- Alignment: Position the loading text or button left, center, or right to match your layout. Center alignment is common for a clean, balanced look. Left alignment works if you want it to align with your post content. Right alignment is less common but can work for specific designs.

- Spacing: Add padding around the loading text or button so it's not too close to the posts above it. This creates visual breathing room. Adjust margins above and below for more separation. Top margin helps separate it from the last post, while bottom margin provides space before any footer content.

- Colors: Set a text color that fits your theme. Many sites use a muted grey color for loading text so it doesn't compete with the main content. For button type, you can style it like a regular button with background colors, borders, and hover effects.

- Typography: Adjust the font size, weight, and style of the loading text or button to match your design. Smaller, lighter text works well for loading messages, while button text might need to be more prominent.

Settings and options

- Load type: Choose between "Infinite" (auto-loads on scroll) or "Button" (user clicks to load more). Infinite type automatically fetches more posts when the user scrolls near the bottom. Button type shows a clickable button that users must click to load more content. Button type is better for users who want more control or have slower connections.

- Button text: For button type, edit the text directly in the editor. Common examples include "Load More", "Show More Posts", "Load More Articles", or "See More". You can apply basic formatting like bold or italic. Keep it short and action-oriented.

- Loading text: For infinite type, edit the text directly in the editor. This appears while new posts are being fetched. Examples include "Loading more posts...", "Fetching more content...", "Loading more stories...", or simply "Loading...". Keep it brief and friendly.

- No More Content text: Set the message shown when all posts are loaded. This appears after the last batch of posts has been displayed. Edit this in the sidebar settings (not inline). Examples include "You've reached the end", "No more posts to load", "That's all for now", or "Thanks for reading!". This gives users closure and confirms they've seen everything.

- Trigger distance: For infinite type only, adjust how close to the bottom the visitor needs to be before more posts load. This is measured in pixels or viewport height. Smaller values (like 200px) mean loading happens later, when the user is very close to the bottom. Larger values (like 800px) mean posts are requested earlier, providing a smoother experience on slower connections. The default is usually a good balance, but you can adjust based on your content length and user experience goals.

Tips

- Use friendly, short messages such as "Load More" or "Show More Posts" for button text, and "Loading more stories…" for loading text. Avoid technical jargon or overly formal language.

- Works especially well on blog layouts where each post has a featured image and title. The visual flow keeps readers engaged as they scroll.

- Make sure your Query Loop is set to show only a certain number of posts per page (for example, 6 or 9) so there's content left to load. If the Query Loop is set to show all posts, the Infinite Scroll block won't have anything to load.

- Test on different devices and connection speeds. Infinite scroll works best on fast connections, while button type is more reliable on slower connections.

- Consider your content length. If posts are very long, users might appreciate the button type so they can control when to load more. If posts are shorter, infinite scroll creates a better flow.

- The block only works when placed inside a Query Loop. If you don't see it working, make sure it's actually inside the Query Loop block, not just after it.

- For accessibility, the button type is generally preferred as it gives users more control over when content loads, which is important for users with slower connections or assistive technologies.
